# D. Token REVOCATION

Two token families must both be handled: OUR session (access JWT + refresh rows) and the FIREBASE session on the device (Firebase refresh token + 1h ID tokens). Plus FCM device tokens and, for Apple users, Apple's own grant (account-flows.md J3/J4).

## D1. Revocation matrix
Legend: R1 = revoke this session row; RA = revoke ALL session rows of the actor; KS = access-token kill-switch (D3); SID = `sid` session check in the guard (backend-nestjs.md E4) [NEW]; FB = `getAuth().revokeRefreshTokens(uid)`; FD = `updateUser(uid,{disabled:true})`; FX = `deleteUser(uid)`; FCM = remove device token(s) (`aks-fcm-webpush`); CL = client clears local state.

| Event | Our refresh rows | Access tokens in flight | Firebase | FCM | Client | Notes |
| --- | --- | --- | --- | --- | --- | --- |
| Logout (this device) | R1 (by presented refresh token; idempotent) [VGA Sanad] | SID check rejects it immediately [NEW]; else let expire (short TTL) | `FirebaseAuth.signOut()` on device only; NO FB (would kill other devices) | Remove THIS device token server-side inside `POST /auth/logout` (owner resolved from the refresh token) [VGA Sanad `deviceToken`] | CL + Google signOut (client.md F4) | Must be a server call; client-only logout = gap (caffeine-app, Letsplay, CareLink, Cozzy) |
| Revoke one session from "active sessions" list | R1 by session id + actor ownership check [VGA Sanad `revokeSession`] | SID check (guard loads `auth_sessions` by `payload.sid`, or Redis `revoked:sid:{sid}` TTL = access TTL) [NEW] - without it the access token stays valid until expiry | none | Remove that session's device token if stored per session [NEW] | - | 404 if not owned |

## D2. Firebase-side mechanics [DOCS manage-sessions, errors, Node reference]
- `revokeRefreshTokens(uid)` revokes ALL Firebase refresh tokens of the user (every device) and sets `tokensValidAfterTime` on the user record to the current UTC time; the server calling it must have a synchronized clock [DOCS]. Firebase ID tokens already issued stay cryptographically valid until their 1h expiry.
- `verifyIdToken(token, true)` (Python `check_revoked=True`) first checks whether the user is disabled -> `auth/user-disabled` (Python `UserDisabledError`), then whether the session was revoked -> `auth/id-token-revoked` [DOCS Node `BaseAuth.verifyIdToken` reference]. The revocation comparison works in whole seconds (`tokensValidAfterTime` converted to seconds in the official samples) [DOCS].
- Cost: one extra network round trip per verification [DOCS]. Policy: use `checkRevoked` on the login exchange (`/auth/social`), `/auth/link`, account deletion, and any endpoint that accepts a Firebase ID token directly; do NOT verify Firebase tokens per API request in Pattern 1 (our JWT is used there). If a Firebase-token-per-request design is chosen, cache `tokensValidAfterTime` per uid for 1-5 min.
- Automatic Firebase revocation happens on user delete, disable, password/email change, password reset [DOCS]. It does NOT touch our sessions - our RA/KS must still run.
- `disabled: true` blocks new sign-ins and refreshes; `deleteUser` removes the user (next login creates a NEW uid -> our link by `firebaseUid` will not match; E3 then returns `ACCOUNT_LINK_CONFLICT` unless the old account was anonymised; handle per social-login.md B8).
- Firebase revocation never invalidates OUR refresh tokens and vice versa. Always do both on logout-all/ban/compromise.

## D3. Own-JWT mechanisms (pick one kill-switch; rotation always)
1. **Rotation + reuse detection** [VGA Sanad `token.service.ts`, with a fix]: atomic `findOneAndUpdate({tokenHash, revokedAt:{$exists:false}, expiresAt:{$gt:now}}, {$set:{revokedAt:now, revokeReason:'ROTATED', lastUsedAt:now}})`; if nothing matched, a non-mutating `findOne({tokenHash})`: revoked AND unexpired -> reuse -> `revokeAll(actor)` + 401; expired (revoked or not) -> plain 401; unknown hash -> 401 (same generic body for all, no oracle). **KNOWN SANAD BUG** (verified read-only, `Sanad/backend/src/modules/auth/token.service.ts` ~79-95): Sanad's claim filter has no `expiresAt` condition and checks expiry after claiming, so an expired token gets marked revoked, returns 401, and a client retry of that token then triggers reuse detection and revokes ALL sessions. Use the filter above (full code: backend-nestjs.md E4). [NEW] also set `reusedAt` on the reused row and `replacedBy` (new session id) for forensics.
2. **Grace window** [VGA Fursatuk `REFRESH_REUSE_GRACE_MS = 30_000`]: a revoked token re-presented within 30s of its rotation is treated as a parallel refresh, not theft. Caveats: Fursatuk issues a NEW pair in that case (an attacker inside the window also gets one), and its rotation is not atomic (security-testing.md H). Safer [NEW]: within grace, return 409/401 `REFRESH_RACE` without issuing, and let the client's single-flight (client.md F3) pick up the winner's tokens; or keep the grace but only for the same `deviceId`. Prefer client single-flight + 5-10s grace max.
3. **Timestamp invalidation**: `user.tokensValidBeforeSec` (Al Mudarib `sessionInvalidatedAt`, caffeine-app `tokensInvalidBefore`); guard rejects access tokens with `iat < tokensValidBeforeSec`. Store the cut-off FLOORED to whole seconds because `iat` has 1-second precision - comparing `iat*1000 < Date.now()`-style millisecond values rejects a pair issued in the same second right after the bump for its whole life (breaks "password change keeps the caller logged in"). Firebase's `tokensValidAfterTime` check is also second-granular [DOCS]. Requires guard DB read (or cache). Set it on logout-all, password/phone/email change, ban, deletion - not just one event.
4. **Token version** `tv` claim [VGA Cozzy]: `user.tokenVersion++` invalidates everything; same DB-read requirement; exact (no clock involved) - **preferred for revoke-all-then-issue-new-pair flows** (password/phone/email change): increment first, then issue the new pair carrying the new `tv`.
5. **Redis denylist** [VGA Buzz `banned:{sub}`, TTL = access TTL + 1h]: per-actor key for ban/force-logout; per-`jti`/`sid` key (`revoked:sid:{sid}`, TTL = remaining token life) for single-session logout. Fail policy if Redis is down: fail closed on admin routes, documented decision elsewhere.
6. **DB re-check every request** [VGA Al Mudarib guard re-loads user]: simplest strong option - also catches role changes and deletion. Cost = 1 indexed read per request (cache 30-60s if hot). Pure stateless guards trust stale roles until expiry (Amirni dashboard trusts payload - gap). Add the `sid` session lookup (backend-nestjs.md E4) to make single-session revoke immediate.
Recommendation: rotation (1) + short access TTL + (4) or (6) with the `sid` check; add (5) only where an instant cut-off is required at scale.

## D4. Ordering rules (logout-all / ban / force-logout / compromise / deletion)
1. Mark user state first (`isActive=false` / `tv++` / `tokensValidBeforeSec=floor(now)`) - blocks new logins and in-flight access tokens. (Password/phone/email change is NOT a D4 event: it keeps the current device; see D1.)
2. Revoke all our refresh rows (`updateMany revokedAt=now, revokeReason=<event>`).
3. Write Redis kill-switch if used.
4. Firebase: `revokeRefreshTokens(uid)` (or `updateUser disabled` for ban; Apple revoke (account-flows.md J4) -> `deleteUser` for deletion).
5. FCM: remove ALL device tokens (`aks-fcm-webpush` `clearAll(actor)`) for EVERY D4 event - logout-all, ban, force-logout, compromise/reuse, deletion - so no push leaks to a device that is logged out or possibly stolen.
6. Audit log (actor, target, reason, counts; never tokens).
Steps 4-5 call external services: run after local DB steps, retry via queue/outbox on failure, never roll back steps 1-3 because an external call failed. Each step idempotent.

## D5. Cross-skill notes (`aks-fcm-webpush`) - this skill is the source of truth for WHEN, that skill for HOW
- **Single-device logout: server-side removal is preferred.** `POST /auth/logout { refreshToken, fcmToken }` removes the FCM token on the server in the same call, resolving the owner from the refresh token (works even if the access token already expired) [VGA Sanad: `logout` -> `deviceTokens.unregister(actor, dto.deviceToken)`].
- **Client step**: call `aks-fcm-webpush`'s `disable()` helper (web: `references/client.md` `disable()`; Flutter: its equivalent DELETE + `FirebaseMessaging.instance.deleteToken()`) rather than a raw `deleteToken()` - `disable()` also clears the locally stored token and avoids loading the SDK when there is none. Its `DELETE /notifications/devices` call is redundant after the server-side removal: it must be idempotent (404/204 both fine) and may be skipped or fail silently (it is already wrapped in try/catch there) - the local `deleteToken()` is the part that matters.
- **clearAll scope**: `aks-fcm-webpush` `references/server.md` lists `clearAll(actor)` only for suspension, force-logout and account deletion. This skill ALSO requires it for **logout-all** and **compromise / refresh-reuse detection** (D4 step 5). That skill's list should be updated to match (not edited from here); until then, follow D4.
